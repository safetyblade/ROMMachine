# CARTDECK — HOT-03 Unified product navigation
Owner direction approved 17 November 2026. Sienna Vale design; Daniel Mercer architecture review; Elliot Shaw delivery; Marcus Reid verification. Design handoff only; no runtime functionality or build validation claimed. Companion to HOT-01/02 draft PR #312. Retain active lanes and merge against current release baseline only.

## 1. Product information architecture
Four adult product destinations in order: Shelf / GEM / SafeSave / CARTMOD. Shelf is the home and only ROM collection browser. GEM discovers and rates; SafeSave protects progress; CARTMOD prepares and modifies playable cartridges, including PC setup. Profiles are a persistent header entry once profile capability is delivered; settings and info remain available. Junior enters its own single-cartridge My Playroom, never adult dock. No dead destination, coming-soon tile, or simulated action in shipped navigation. Show dock only when two or more real destinations are available, otherwise reclaim its height; preserve existing Done/Tools/Undo arrangement dock. Stable destination IDs, not positional tab indices; restore selected destination and shelf context on Back. Use existing theme tokens and named resources; no new dependencies.

## 2. Shelf interactions and visual contract
Header: CARTDECK wordmark / LIBRARY, info, settings, profile (when live), existing overflow. Compact pinned search immediately below header, clear X, submit dismisses IME; search reacts to title, display name, filename and system labels, case insensitive. Search stays on Shelf. Back dismisses keyboard, then clears query/filter context before navigating away. Touch filter button bottom end above safe insets/dock, visible count or selected-state marker; reserve space so no final cartridge is blocked; hide in arrange mode. On TV/controller, equivalent filter entry in header and reachable focus target. Filter popover/sheet: Favourites only toggle; console multi-select with counts from authorised collection; recent played toggle; sort My arrangement (default), title A–Z/Z–A, console, last played. Clear all; Done closes. Filters combine AND across groups, OR across selected consoles. Active chips removable; count and empty states distinguish empty library from no matches. Never silently switch to Covers on filtering; optional dense Covers is secondary, same catalogue. Keep five spines per normal portrait phone row, face cartridges occupy three slots, accessibility scaling respected. Use existing GC-NAV/TV implementation for horizontal section navigation and vertical within section; do not introduce competing focus/scroll mechanisms.

Unfiltered custom arrangement preserves sections, manual gaps, orientation, order, hidden restrictions, scroll anchor. Filtered results are temporary derived projection of authorised games, compacted with no artificial missing-game gaps; may preserve current facing where practical; temporary sort must never call edit/autoArrange/reconcile with subset. Reset returns exact saved arrangement and scroll anchor. Disable arrangement mutation in filtered view; entering Arrange first restores unfiltered permitted shelf with clear indication; exit restores prior filter context. Existing add cartridges, refresh, resume, permission warnings, custom artwork/rename, game detail/launch and long-press actions retained. Favourites: small filled heart on fav spine/front (top-right safe surface, not title/system, no custom-art obstruction); normal cartridge does not show permanent empty heart. Toggle in detail/context and accessible focused action; touch target >=48dp without reducing artwork; use existing Favourite interactor. Immediate Room observation; no secondary favourites table. Current Game.isFavorite is single-user only; later profile-scoped adapter replaces it atomically when JR-01 ships. No claimed profile isolation before that.

## 3. GEM flow
GEM landing: For You / Browse / My Ratings; cold start offers neutral discovery and explicit rating, never fake personal recommendations. Result card: artwork or fallback, title, console, reason, evidence/availability when known. Owned and verified-eligible -> open canonical Shelf cartridge and play through existing launch. Not owned -> details/metadata only; no ROM download. My Ratings: edit/remove explicit owner score; do not treat RoxyRating/critic scores as user input. Use GemRatingRecommender and reviewed catalogue + verified identity per docs/gemrating/OFFLINE_ENGINE_CHECKPOINT.md. Release only after licensed metadata, local ratings persistence and authorisation/eligibility integration; no Junior discovery shortcut.

## 4. SafeSave flow
SafeSave landing: current player / save inventory / backups / recovery / export / import. Group by canonical cartridge, engine and save type; memory card location and shared scope explicit. Export: choose current game / player / all permitted players, preview file counts, unsupported exclusions, choose destination, verify archive, receipt. Import: inspect manifest/identity/profile, conflicts preview, copy or confirmed backup-and-replace, verify and receipt. Cross-player copy requires authorisation, source stays intact. Local backups/recovery available only when real handlers support them; Vault separate future permission/account stage. No ROM/BIOS/firmware upload. Existing saves and frozen aliases preserved; source of truth is existing JR01 architecture and SAFESAVE_FORMAT_AND_API_V1.md; no parallel save system. Standard only own saves; manager cross-profile after gate; Junior no unrestricted access.

## 5. CARTMOD flow
Landing: Setup PC game / Mods & patches / Cartridge tools / Manage installations (show only implemented actions). Cartridge entry point from Shelf detail "Prepare in CARTMOD" or "Manage installation" carries immutable cartridgeId; return to same shelf location. Normal ready game still launches directly from Shelf. CARTMOD owns preparation UX; PC lane owns actual guest/native execution; MOD-01 owns mod engines. Use canonical shared cartridge registry, not separate game library.
PC setup wizard: choose PC game media (explicit user-provided file via SAF) -> select supported runtime/guest path based on real capability -> attach optional user-provided OS media -> review storage estimate, identity, permissions and compatibility -> create isolated staged installation -> launch guest installer / disc switch via PC engine -> choose installed executable if supported -> verify launch readiness and persistent guest storage -> register ready cartridge or mark existing setup incomplete -> Open on Shelf. For current DOSBox Pure path, reuse Settings PC Classics import and managed DOSZ vault; separate import success from boot/install verification. Do not label an imported ISO "ready" just because archive created. Existing provisional cartridge can remain recoverable with setup-needed state, launch setup through CARTMOD; publish playable status only on actual capability evidence. Resume/cancel/repair/reconfigure, manage media and storage; destructive removal requires explicit impact preview and backup/retention policy; preserve previous ready cartridge and saves on failure. Show DOS/Windows guest option only if runtime supports it; Wine/CPU translation not exposed until verified. No bundled commercial media, no auto-execution of arbitrary host files, no external frontend, no new engine in HOT.
Mods flow: select original cartridge -> choose supported patch/texture package -> inspect source hash, target support, storage impact, save choice -> stage immutable separate edition -> verify -> enable/disable or revert -> open cartridge. Unsupported package, mismatch, failed extraction, interrupted operation remain recoverable; original and saves never overwritten. MOD-01 file engine groundwork is not finished integration; depend on actual persistence, SAF, deployment/rollback and QA. Advanced PC setup (guest display, keyboard/mouse and controller profiles, executable/launch config) lives here, not gameplay navigation; universal menu holds in-session controls and settings as already approved.

## 6. Profiles, Junior, responsive
Profile switch from header, not dock; local profiles vs optional account clearly separate. Manager/standard/Junior permissions per JR01 product spec and parent contract; access checked at repository and launch, deep link, focus, not just hidden UI. Profile switch during game through existing save/session close contract. Portrait fixed search + floating filter; landscape/tablet full viewport with compact header, optional side popover; TV/DeX controller-first focus across header/dock/sections; focus returns to opener on close, Back closes overlay before leaving, no click-through into shelf. Do not add independent TV navigation engine; coordinate GC-NAV-01/GC-TV-01. Existing handheld visual system and palette tokens retained.

## 7. Source implementation map

Inspect ShelfLayout.visibleSections before using subset; do not persist projection. Do not alter library migrations or saves for HOT.
C: Navigation adapters only after actual GEM, SafeSave, CARTMOD routes available; preserve existing save-sync/settings and PC Classics entry until live replacement redirects verified. Product features implemented in respective lanes, not placeholder UI. Existing GEM offline engine & MOD-01 groundwork do not justify visible product tabs alone. Profile and SafeSave domain contracts JR01.
D: integration into latest GC and release branch; cherry-pick HOT-01/02, resolve conflicts without reverting intervening GC/PC/CI; no engine, native packaging, schema, CI or signing changes as HOT. No standalone full native build triggered by design commit. Build/test actual release source before distribution.
