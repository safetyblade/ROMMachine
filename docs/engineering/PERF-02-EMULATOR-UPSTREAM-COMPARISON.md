## Source-level findings and bounded next actions

### Confirmed source/configuration defects and risks

1. **PPSSPP assets update can destructively remove prior assets on failure.** `PPSSPPAssetsManager.kt` pins `PPSSPP_ASSETS_VERSION = "1.15"`, deletes the current assets directory before validating the downloaded ZIP and deletes it again on throwable. Archive entries are joined without canonical path validation (zip traversal risk). The version flag can be written even if the body is null. **Do not execute an asset refresh unchanged.** Proposed bounded fix (separate approval/PR): stage to temporary directory, reject traversal, validate manifest, atomic swap/rollback; preserve old assets on network/update failure. Ticket #60.
2. **PCSX ReARMed DRC is explicitly disabled by default.** `GameSystem.kt` sets `CoreVariable("pcsx_rearmed_drc", "disabled")`; the core exposes that option, but source has not confirmed the exact runtime-reported key/value or ARM64 implementation. A controlled A/B test of enabled dynarec plus upstream refresh is justified; do not assume Dead Ball Zone's match freeze is simply slow FPS. Tickets #56/#61/#79.
3. **PSP support assets and core binary are independently versioned.** The v1.15 asset URL is inherited from LemuroidCores, while `CoreID.PPSSPP` is a separate .so. A current core plus stale/missing assets can give compatibility/load failures. Match asset bundle to selected core under a reversible version switch; do not equate image failure in official PPSSPP with CARTDECK-specific frontend failure. Ticket #60.
4. **N64 duplicate-frame settings require instrumentation.** `mupen64plus-FrameDuping=True` and `skipDuplicateFrames=false` are configured together. This may be intentional but actual runtime options, GL buffer/presentation cadence and audio underruns need device traces before changing them. Ticket #60.
5. **NDS state and viewport preservation.** `melonds` uses `statesVersion=2`, threaded renderer and touchscreen defaults; replacing it with the newer melonDS DS lineage without explicit SRAM/state migration could lose progress. Current DS viewport is owner-accepted; keep its geometry. Ticket #60.
6. **3DS is Citra-only in current registry.** `SystemCoreConfig` hardcodes `statesSupported=false`, arm64-only and several rendering defaults. Azahar Android maturity does not prove a compatible LibretroDroid core or save-state port; perform a separate in-process Android host proof. Ticket #60.

### Plausible improvements — not yet executable proof

- **PSP high:** compare exact libretro PPSSPP build/revision with the official latest upstream `[d6c4cc55a173]`; isolate texture backend, JIT and decoded game stage; evaluate native PPSSPP adapter only after measured Libretro gap. Preserve per-engine user saves. Owner's independent PPSSPP failures make bad media/compatibility a possible diagnosis, but there is no evidence to accuse any disc.
- **PS1 high:** compare inherited PCSX ReARMed binary with upstream `[7b0e8f8fadfb]`; check dynamic recompilation, core options and title entrypoint in controlled A/B, then SwanStation for match-load compatibility; DuckStation reference is subject to exact licensing review. Never copy proprietary emulator binaries or assume compatible save states.
- **NDS/N64 medium:** benchmark maintained melonDS and Mupen64Plus-Next alternatives on the actual target phone with identical legal fixtures; prefer no change if current version is stable.
- **3DS medium:** test Azahar Android graphics/input and in-app JNI feasibility; keep old Citra as reversible default until full save/title acceptance.
- **Other cores low:** retain Gambatte, mGBA, Stella, FCEUmm, Snes9x, Genesis Plus GX, FBNeo, MAME, PCE, NGP, WonderSwan, DOSBox Pure, etc. unless a concrete defect or compatibility win is found. SameBoy is a GB/GBC accuracy reference, not an automatic upgrade.

### Required evidence before any upgrade

Build exact ELF/core hashes and provenance from pinned `fee2e824` + installed APK; verify compiled CPU/backend flags, `retro_get_system_info`/core options and ARM64 dynamic linking; run lawful reproducible titles on a physical Android phone, 15–20-minute nominal speed/frame pacing/audio underrun/memory/thermal logs; record SRAM vs state/save paths and same-signing in-place update. Capture baseline and candidate metrics, preserve original binary/assets, and implement a per-core rollback before changing a production default.
