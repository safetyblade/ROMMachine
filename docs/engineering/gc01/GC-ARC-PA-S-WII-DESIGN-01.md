## Preserve
Existing registered device modes Sideways=513 (default), Classic=1025, Nunchuk=769, GameCube=1; controller choices per cartridge, live switch, core-advertised mode authority, Standard Wii.kt and approved solo geometry. Do not add a fake fifth device ID. Separate CARTDECK Menu from verified guest Home. Release prior device's held and momentary inputs before mode change. Nunchuk +/- L1/R1 are labelled by current Standard source; generic Start/Select are separate host IDs and not proven aliases. Audit guest descriptors before removing/relabeling. Existing Sideways has no stick, Shake=R2; Nunchuk separate remote and extension shake L2/R2. No global button remap.

## Design candidate WII-S01
Three independently saved settings at cartridge scope: controller type; pointer mode (where supported); motion method (where supported). Expose in first-open and gameplay Controls/Setup consistently; defaults retained. Existing core dolphin_ir_mode 2 touch, 1 stick, 0 relative. Apply only native verified modes. For Nunchuk use same approved A/B/C/Z action island, fixed A/B/Z Holds and mid-arc separate shakes; left movement stick and central D-pad retained. In Stick mode retain dedicated right IR stick; Touch mode remove IR stick from active hit targets and leave optional display-safe empty/compact housing; use actual game screen IR mapping, not invented cursor; Relative mode dedicated pointer pad if native relative input can be delivered, otherwise retain existing supported gesture surface. Do not shift accepted action centres just because pointer seat changes; if compact shell conflicts return for review. IR re-centre/offscreen/reacquire only if actual guest dispatch supports it. Standard retains two-hand access, same settings and native ownership; no mandatory PivotARC. Use per-mode explicit input role labels, no ambiguous second analogue for pointer.

## Design candidate WII-S02 upright Remote
Proposed compact digital remote: central D-pad, A/B lower/right primary face seats, 1/2 upper radial seats, fixed A/B Holds, +/- and verified guest Home on rail, Shake mid-arc, optional verified pointer seat outside main thumb path. Suggested schematic 360x350 D(105,145), 1(167,65), 2(231,105), A(231,218), B(166,263), Shake(231,162), HA(298,218), HB(166,321). Existing Sideways profile remains unchanged. Upright profile gated on genuine native core device/orientation path with correct directional and IR mapping; never re-label Sideways without actual guest behavior. Geometry illustrative, measured 48dp+ targets and viewport fit required; independent pointer seat needs fit assessment.

## Motion design
Offer Button Shake (existing); device motion (conditional sensor bridge, calibrated neutral, rotation transform, lifecycle neutral, per-cartridge sensitivity); manual directional motion pad (conditional actual core axes; drag returns neutral); MotionPlus (conditional real angular velocity and calibration guest channel, not ordinary shake). No gesture macros or fake gyro; do not expose unsupported actions as usable. Separate remote and Nunchuk motion. In-game calibration/tester under Controls, advanced diagnostics under Advanced. Input mode switches do not restart core or reset NAND. Keep stable touch targets and no overlay over direct touch viewport. If native bridge absent, report blocker with exact pinned source and retain working modes.

## Tests
Standard and PivotARC each: New Super Mario Bros Wii (1/2 and shake), Mario Kart Wii (tilt), Super Mario Galaxy (move + pointer + shake), Metroid Prime Trilogy (IR), Wii Sports Resort and Skyward Sword (MotionPlus), Brawl (Classic/GameCube where supported). Validate title-specific requirements before acceptance. Verify mode persistence independent cartridges, actual native device selection, +/- aliases, no stuck keys, independent pointer/button/movement, handedness, rotation, release, fallback and save continuity. Build source gate first. Owner review on material design changes; source bridge proof before enabling. No GripARC or Joint.
