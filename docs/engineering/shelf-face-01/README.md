## Player path and data contract

Arrange shelf → select a cartridge → **Show front** / **Show spine**. Browsing either view still selects the existing detail journey; Open remains explicit. Long press, sections, vacancies, sort and Undo retain their existing entry points.

`ShelfCell.facing` is optional additive presentation metadata in `cartdeck/shelf-layout-v1.json`, format version 1. Missing, null and unknown values decode as SPINE without resetting the rest of the shelf. Stable cell IDs and existing system/file-URI keys remain authoritative. No Room migration, ROM, save binding or emulator configuration changes.

A front reserves three slots, a spine/vacancy one. Greedy packing preserves stored order and explicit empty rows. Padding is renderer-only. At one/two-slot widths a front keeps its selected facing and scales proportionally within the row. The canonical 320:390 front and 94:340 spine share a rail baseline at ordinary widths. Artwork uses the existing Fit/custom/indexed/fallback renderer and Room invalidation revision; replacement at the same custom URI invalidates the visible shelf request.

Turning uses two 110 ms Y-axis phases, with the atomic state/content/footprint exchange edge-on. The asynchronous disk commit can lengthen elapsed time between phases. Reduced Motion or Android's disabled animator scale swaps immediately. Dragging cannot flip; the full item footprint supplies before/after insertion targets, while reserved vacancies retain swap semantics. Pickup remembers whether its measured source is already front-facing.
