# Original Xbox engineering backend

Xbox (`xbox`) is an independently gated native backend, not a Libretro core. The normal scanner verifies XDVDFS volume signatures and `default.xbe`/XBE certificate data for `.iso` and `.xiso`. Existing shared-ISO detection and refresh handling are retained. Xbox registration is present only when the engineering native-system list contains `xbox`.

`GameLauncher` routes Xbox to an internal `NativeCoreActivity` in `:xbox` under the same application identity. The adapter retains `com.rfandango.haku_x.NativeCoreActivity` solely because those are the pinned upstream JNI symbol names. It does not import hakuX's launcher, library, branding, updater or external intents. SDL3 manages Vulkan surface/audio and Android lifecycle. FEX's one-run state is destroyed with only the Xbox process. Errors return to the shelf without automatic crash restart. A title-requested XBE relaunch is relayed through the main process after the old game lock releases, with at most five restarts within 30 seconds. Upstream currently calls `_exit(0)` on SDL QUIT because its core thread has no stop API. Process containment is implemented; graceful engine draining and authentic HDD-save round trips remain unverified.

Conventional input includes simultaneous D-pad, A/B/X/Y, Black/White, Start/Back, analog sticks and analog triggers. USB/Bluetooth gamepads use Android gamepad events; shoulder buttons map White/Black. Touch input uses the existing CARTDECK PadKit Standard layout and native hardware seats with Xbox A/B/X/Y, Black/White, LT/RT and Back labels; existing Start/Select touch positions are unchanged. Original/Pink/Green and stored custom appearance are shared with the normal gameplay shell. PadKit owns simultaneous touches and both sticks; hardware triggers retain proportional pressure, while touch trigger buttons send full pressure. Pause/Resume and Return to shelf are internal. The renderer is fitted inside the controller viewport; native `aspect=auto` preserves the game's own aspect.

Persistent data is `files/native/xbox/hdd`, including `Partition1/UDATA`, `Partition1/TDATA` and `eeprom.bin`. Native shader data is the sibling `files/native/xbox/hle`. Neither is installed inside a disposable core revision. Before a different engine revision opens existing HDD data, the launcher writes a complete ZIP to `files/native/xbox/backups/before-<old>-to-<new>-<unique-id>.zip`; insufficient space or failed backup prevents launch and leaves original data intact. Upgrading the same-package signed APK retains this location. Quick states are not implemented or claimed as HDD persistence. Open/Resume starts the game with its real persistent HDD data.

The host checks Android 9+, ARM64, Vulkan 1.1+ feature presence and Android low-memory state, exact engine hash, SDL3 presence and seekable URI access before launch. Detailed unsupported GPU/JIT/game errors are reported by the native engine. No custom graphics driver is installed automatically; this slice uses the system Vulkan driver. No BIOS, dashboard or game content is bundled.

Tests exercise synthetic disc structures, simultaneous input, trigger values, engine-upgrade backup and storage identity. These are contract tests, not evidence of real gameplay. Physical ARM64 frame/audio/input/save round-trip and APK upgrade gameplay remain **NOT TESTED** until performed on a device with a lawful game/homebrew fixture.

The verified complete runtime (SDL, hakuX and native hook libraries) is copied read-only into `files/native-engines/xbox/versions/<revision>-<corehash>`. Atomic active/previous selections permit explicit pause-menu rollback; the selected SDL and core paths are loaded only after a process restart. All native dependencies are checked against APK-provided hashes before use. Persistent HDD and shader data stay outside this immutable cache.

## Issue #143: bounded first-presentation recovery

Owner evidence is SM-S721B (Galaxy S24 FE, Exynos 2400e / Xclipse 940), indexed disc followed by a white screen. No VkResult, native fatal trace or logcat was supplied, so the underlying device failure is unresolved. Pinned hakuX v1.3.0 already includes the upstream Xclipse capability paths: BC-format probing when the BC feature is absent, a descriptor-backed uniform block when push constants are too small, D32S8 fallback and the Vulkan 1.1 extension path. Do not force Adreno driver overrides on this device.

The integrated activity previously polled fatal/quit only and could wait forever. It now bounds startup to 90 **foreground** seconds, excluding background time, and pauses with a copyable sanitized report and explicit return to shelf when no guest frame is presented. The report records engine identity, model/API and last known boot/presentation stage, without source URI, title or private paths. Stored at app-private `native/xbox/last-launch-report.txt`. A visible surface is not success. It does not auto-relaunch or alter HDD data. Existing title-relaunch cap and controller bridge remain intact.

Upstream `nativeGetFrameShown` previously latched when a guest image was acquired **before** `vkQueuePresentKHR`. The new source patch uses a thread-safe latch set only when Vulkan accepts a successful/suboptimal presentation containing a guest frame. A rejected present or a clear-only swapchain image does not pass startup. This is driver acceptance evidence, not proof of correct pixels, audio or gameplay. `nativeGetBootState` distinguishes FEX/kernel boot from a running core waiting for presentation; granular GPU/device/extension data remains in the native logcat.

Capture Vulkan physical-device properties and VkResult before changing capability defaults. A successful accepted present still requires owner verification of rendered gameplay, audio, controls and HDD save/reopen.
