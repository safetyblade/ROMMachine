# XGFX-01 — Xenia shared-memory reliability

Baseline: accepted PERF A–E 54afc6f1; APK 91018030. Pinned XenDroid 779680ade075d2d2a4c589c6a8d57a8e26c116c0 unchanged. Related #295.

The existing optional frame-end page refresh copies GPU-authoritative flags into the valid flags using a dirty bitmap. MakeRangeValid marked chunks dirty only on GPU writes, not CPU-only uploads or CPU ownership changes. Thus the optional refresh can retain valid pages it should invalidate. Test against actual pinned methods, 4/16 KiB page size, boundary/overflow/zero range and 10,000 repeated ownership changes. Invalid ranges conservatively disallow upload hoisting. This is an evidenced bookkeeping defect, not established as the cause of the owner-reported FIFA Street 3 deformation; the existing clear_memory_page_state default stays off. No new configuration/UI, no forced global wait or change to resolution/pacing.

Review of pinned command processor: Beg​inSubmission resets bound descriptor state, frame opening invalidates texture hash and constant descriptor validity before retiring frame-indexed pool pages. Existing #309 interpreter constant hypothesis was withdrawn: dynamic indexing includes all 256 constants. Do not remove these protections or reinstate speculative patch. Memexport routing, noncoherent readback, vertex/index fetch formats and lifetime across mid-frame submissions still need targeted runtime evidence before further change. No claim of complete graphics repair.

CI: existing emu-recovery native producer rebuilds only changed Xenia recipe; Cemu may reuse source-matched receipt, unchanged LibretroDroid selected from accepted A–E build, remaining native receipt validation mandatory. Standard APK, separate PS3 lane. Retain exact prior Xenia artifact and on-device rollback path. Owner test identical FIFA Street 3 match for 15–30 min, rematch, pause/resume, cold/warm launches, and another 3D Xbox 360 title. Audio, inputs and saves regressions checked; no measured speed claim.
