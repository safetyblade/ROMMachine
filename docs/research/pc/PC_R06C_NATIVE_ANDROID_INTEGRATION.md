## Native Android path (initial PE32 candidate)
Use Wine 10.0's upstream wineandroid.drv (TextureView, Android Surface, touch and hardware keyboard/mouse) with source-built native ARM64 Wine, not a second app or Linux Wine archive relabelled as Android. Box64 0.4.4's ARM64 PE wowbox64.dll is a distinct experimental WoW64 CPU backend, selected for i386 by an exact source patch. This is a deliberate additional route for the Shandalar-first Win32 target; Linux x86_64 Wine + Box64 remains a separate R06B gate and is not replaced by this candidate. FreeType 2.13.3 is built for Android; llvm-mingw toolchain and source commits are pinned. No prebuilt Winlator host, no proprietary Windows or game files.

All Wine Android native ELFs are audited for AArch64, Bionic and 16 KiB LOAD alignment, retained as APK native entries. A versioned manifest binds native and PE/data files and each native file is symlinked from a private runtime tree to its packaged counterpart; no chmod-and-exec of writable native binaries or target SDK lowering. Driver's legacy asset extraction and shared prefix are replaced. The patch is intentionally experimental; Android subprocess/loader/SELinux and PE mapping/JIT compatibility, 4K/16K actual runtime, and FreeType path loading must be demonstrated. Runtime components and process are not a security sandbox for untrusted games. Separate PC debug app and owner-selected trusted PE files only; no production enablement.

CARTMOD explicit PE32 import publishes the same stable cartridge UUID and immutable DOSZ transport with distinct Wine marker; never heuristically scans EXEs or runs Wine cartridges in DOSBox. A stored payload is copied once into local-profile/cartridge content, no overwrite. Shelf GameLauncher starts the non-exported :pc_wine host only when PC_WINE_NATIVE_ENABLED. It automatically prepares the prefix, loads Wine's native ntdll using embedded Android driver and submits the actual guest path. Reuses shared CARTDECK gameplay menu, keyboard text, guest-save guidance and prefix-specific server shutdown. Shared game lock is already acquired by GameProcessInitializer: both isolated PC hosts must use acquireExclusive, not reacquire a second channel; process termination releases it. Return result is not a guarantee of a clean Windows shutdown. Actual integrated candidate has independent package ID from production and is not a security boundary within that package.

CARTMOD's runtime verification cartridge exercises the identical launch path as imported PE32 games: actual GDI window, mouse click, K key, S save, close/reopen persisted counter and waveOut A audio probe. Sound backend is not delivered; an audible tone and correct audio device are required, not merely waveOut result. Source-pinned build and APK verification only certify the candidate, not on-device execution. Junior/profile authorization and SafeSave classification of Wine prefix not approved for release. Multi-file and CD installers, 16-bit installer compatibility, installed executable selection, direct post-install launch, actual Shandalar overworld/duel/progress and full normal app bundle remain blocking. No merge.
