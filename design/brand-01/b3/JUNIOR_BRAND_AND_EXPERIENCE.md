# BRAND-01 / B3 — CARTDECK Junior identity and presentation

18 November 2026. Design candidate on the B1/B2 branch. Governing interaction sources: docs/design/jr01/JR01_PRODUCT_UX_SPEC.md Amendment 1 and JR01_FINAL_SCREEN_INPUT_PARENT_CONTRACT.md; this package adds brand/art and presentation, not a new authorization model. B1 classic-by-default, B2 five adult destinations, Light and appearance-reactive tint stay intact. Owner review of new visual assets pending.

## Brand family

CARTDECK Junior is a mode of the same application, not a separate executable or adult dock destination. The approved master C-slot and CARTDECK paths are copied without geometry changes into the Junior lockup; new rounded Junior lettering is an original path-based subordinate wordmark. Tint with the active permitted theme's readable ink or accent. Do not slant, warp or recolor individual letters randomly. On compact screen use My Playroom with the existing C-slot or house mark; don't stack the full lockup above the only cartridge. Grown-Ups uses the shared protected-action lock symbol, not a separate marketing brand or a security guarantee. No Roxy/team, licensed characters, aggressive arcade motifs or mascot required. Tagline "Their games. Their little world." only in introduction/brand specimen, not permanent gameplay chrome.

## Themes and local avatars

Five previously specified choices: Standard CARTDECK (default), Candy Garden, Dino Adventure, Space Explorer, Ocean Friends. Manifest defines room/surface/raised/ink/muted/accent/onAccent/focus. Original exploratory theme backgrounds retained; strengthened foreground and button shades for contrast. Optional single small original line-art motif may occupy background corner, never behind text, game art, controls or focus. Themes are inclusive, not gender assignments; all children can choose from their manager-permitted list. No auto-change based on age, gender, game or player name. Do not store/alter adult appearance settings; map through same existing appearance/material engine with profile-owned preferences once domain support exists. If a chosen theme becomes disallowed, use manager-selected allowed fallback (Standard only when permitted); if policy unavailable, fail closed and use neutral non-interactive rendering until resolved. Respect reduced motion and high contrast; disable decorative motif in high contrast if needed. No sound-only cues or default animated wallpaper. Local avatars: Star, Cat, Rocket, Leaf, Fish, Balloon; tint contrast-safe, accessible label, no real photo or online identity needed. Six original 24-unit SVGs are reusable in chooser/Junior parent editor. No inline external font; B1 font review still applies. Theme manifest is visual DATA, not authorization input. Preserve exact existing cartridge asset geometry and title artwork; do not use theme motifs as game cover replacements except generic branded fallback clearly labelled with actual eligible title.

## 1. Universal player chooser — Who's playing?

Shared console-style profile chooser, not Junior entry only. A single grid/list of local avatar/nickname tiles, role semantics for manager/standard/Junior where useful, selected focus outline not color-only. At least three supported in tests, no fixed three-account limit; use adaptive wrapping and scrolling for more profiles. Add Player/edit permissions only through authenticated Manager entry. No adult-only games or save details in chooser tiles. Respect validated auth before rendering chooser from Junior (including switching to another Junior unless manager policy explicitly permits); no adult dock in this context. Existing first upgrade owner saves remain via architecture contract; remember-player is manager-controlled, and a remembered Junior can't auto-unlock adult. Cancel returns to prior safe context. Profile switch quiesces current gameplay and binds new owner before next launch; no visual "success" until service confirms.

## 2. My Playroom

One cartridge cover is the focal point. One only at ALL times, including transition, preview, Favourite and collection states, on every orientation. No peeking neighbours, no grid, no multi-cover crossfade. On swipe completion replace previous selected cover with new approved cover (reduce-motion immediate); never show a denied title during loading or transition. One cartridge image using existing cartridge rendering/ratio; fallback is neutral branded geometry, not a fabricated game cover. Header small avatar/nickname and optional collection selector using parent-supplied categories. Main cover centered; readable title and optional console badge; play button text "Play" or "Continue" only as confirmed per-profile valid state, with play glyph. Large previous/next targets only when two+ approved entries in current scope; optional count "2 of 5" uses allowed count only. No arrow for one title, no hidden thumbnails. Favourite heart only if permitted, accessible selected state. Grown-Ups discreet but readable lock action >=48dp. No adult dock, GEM, website search, covers search/upload, unrestricted settings or ROM import/delete. Child themes only via allowed picker (one theme preview at a time; no game previews in picker). Child long press offers only permitted child actions. No unnecessary game detail step or launch settings. Restore selected allowed cartridge after game, rotation and reconnect by ID; if removed, choose next permitted title without revealing former title. Empty: original house/cartridge line illustration with "Ask a grown-up to add your games", Grown-Ups only. Missing approved game/engine: neutral "This game needs a grown-up" and safe return; no paths, trace or technical menu. Save failure: honest retry/return options per runtime; no false saved badge. Existing GC-01 menu trigger; child menu Resume / Save Progress if supported / Return to My Playroom. No extra menu key binding.

## 3. Responsive and input

Portrait: compact header + optional short collection control; single card max roughly 50–60% measured body (subject to text/targets), Play below, Previous/Next alongside art or in one row; bottom Grown-Ups action. Use scroll for large fonts, never clip art or primary control. Short landscape: slim header, one cover left/centre and action column right, with name, selected title, Play, previous/next and protected entry; maximize measured usable space, account for cutout/system navigation. Tablet portrait or landscape: one larger capped cover and generous whitespace; same hierarchy, not extra cards. TV: one large central cover, clear label, Play and 5% safe area, focus ring and D-pad traversal; no keyboard/touch requirement. Focus order avatar/collection > selected cartridge/title > previous/next > Play > favourite > Grown-Ups; where device requires first focus Play/selected cartridge, retain deterministic left/right title changes and explicit Back. D-pad left/right advances once per press (repeat only controlled hold); touch swipe one title per completed gesture; no unintended launch on swipe; controller A/confirm only on focused action, B/back safe. Back from child routes never escapes to adult; external OS is not kiosk. 48dp targets, primary >=56dp, 24sp+ child heading where space permits, 16sp readable body, system font scaling; preserve hit targets and one-cover constraint at 2x. No action with only a color/symbol.

## 4. Grown-Ups

Neutral B1 adult presentation, not the child's theme decoration; permission checks before showing any management data, including other names/saves. Child sees only auth entry (PIN/device-backed manager verification per actual approved architecture). Mask input, no secret hints, retry throttling/existing recovery semantics, Cancel returns locked child. No UI-only PIN or fake success. On authenticated Manager dashboard: Players; Junior Game Access; Playroom Personalisation; SafeSave; System / Help. Create/edit/role/archive or delete remains approved profile workflow including retention/export choice, not direct delete. Junior allowlist editor may show multiple ROM rows only in authenticated adult context; search/filter and select by canonical ID, explicit approved count, unknown metadata clearly unknown, preview as child uses actual restrictions. Approve/remove is deliberate, removal never deletes ROM or save. Parent controls allowed themes/avatars, collection groups, permitted favourites and accessibility; preview single-cover and confirm/cancel. Standard player hidden list isn't an allowlist; never conflate roles. SafeSave uses B2 checkpoint symbol and authorized inventory/export/import/copy/recovery; no Vault action before real service; actual verified vs excluded counts, conflict confirmation, no data loss. On return to Playroom end manager context per contract, restore locked mode; no adult tab left accessible via Back. Manager's standard Settings > Profiles & family links to same authorized handler. No child-facing web links, technical diagnostic data, account/storage actions.
